「AI 模型 › 朗读」页：三种整理方案

现在的问题：朗读员、「添加」按钮、各家 API Key 全是同一级的分组，一个接一个排下来，看不出谁属于谁；分组标题「MiniMax · MiniMax」还重复了。下面三种方案都用同样的数据：两个朗读员（MiniMax、Qwen）、系统语音、两家的 key。

A · 列表 + 弹窗编辑B · 按服务商分组C · 顶部再分两栏
结构朗读员一行一个；点一行弹出编辑窗；密钥单独一组，每家一行每家服务商一张卡片：卡片里是这家的密钥和这家的朗读员「朗读员」和「服务商密钥」做成两个小标签页
一眼能看清最清楚：主页只有三层——默认、朗读员、密钥清楚：谁用哪个 key 一目了然清楚，但密钥藏在另一个标签里
改一个朗读员点一下 → 弹窗改 → 完成（和「动作」页编辑动作一样）展开卡片里那一行直接改同 A
和 App 其他页一致一致：「动作」页就是列表 + 弹窗一般页面已有「大模型 / 朗读」一层标签，再加一层会变成标签套标签
我的推荐推荐服务商多了以后卡片很长不推荐

三种方案都会顺手改的：
  • 分组标题不再重复成「MiniMax · MiniMax」；服务商用图标和副标题表示。
  • 密钥行平时只显示状态（已保存 / 未设置），点「更改…」才出现输入框；没保存密钥的服务商，它的朗读员旁边提示「缺少密钥」。
  • 「添加」只有一个按钮，点开再选服务商，不再每家一个大按钮。

这是网页模拟，控件样式和 App 里的 SwiftUI 实物会有细微差别；选定后以 App 截图为准。
