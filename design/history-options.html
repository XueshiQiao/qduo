QDuo · 历史记录 —— 方案与原型

先看「总体方案」：存什么、存在哪、怎么跟每种动作绑定、怎么复现。后面三个页签是三种页面布局的可点击原型，共用同一份底层设计，只是展示方式不同。原型里的数据是虚构的；按钮点下去只弹提示，说明真实版本会做什么。

先说明一件事：GitHub 上没有找到「历史记录」的 issue。我翻了这个仓库全部 12 个 issue（开着的和关掉的都看了），没有一个讲历史记录。离得最近的是 #11「每日用量统计」，但那个只是数次数、发统计事件，不存内容，和这里是两回事。如果需要，我可以把这份方案写成一个英文 issue（你说了我才建）。

1 · 设计从代码里来：已经有两条「类型轴」

历史页面最难的是「类型很多、以后还会加」。好消息是代码里已经把类型拆成了两条独立的轴，历史只要顺着这两条轴走，新类型就能自然接进来。

输入轴：动作的种类（PopBarActionConfig.Kind，14 种）
  • ai —— 翻译、润色、解释，以及你自己写 prompt 的动作
  • systemTranslate —— macOS 自带的离线翻译
  • transform —— 本地文字处理（大小写、JSON 格式化、繁简转换、字数统计…共 23 种）
  • speak —— 朗读
  • openURL / webPreview —— 搜索、打开链接、小浏览器
  • quickLook / revealInFinder —— 预览文件、在 Finder 里显示
  • shortcut / script —— 快捷指令、shell 脚本
  • copy / pause / inspect / settings —— 工具类
  • group —— 只是文件夹，不会运行
输出轴：运行完「呈现什么」（PopBarPresentation，11 种）+ 文字往哪送（ActionOutput，5 种）
  • output(文字) 再按 panel / compare / replace / append / copy 分去向
  • result(文字) —— 报告或错误信息（字数统计、「没配 API key」）
  • openExternal(URL)、webPreview(URL)
  • quickLook(文件)、revealInFinder(文件)
  • speak(文字)
  • none、pause、inspect、openSettings
代码注释里已经写明：以后新加输出类型，就是在这个枚举里加一个 case，再在 PopBarSession.present(_:) 里加一个分支。那个函数是「所有结果的唯一出口」，历史记录就挂在这里。

2 · 整体结构

3 · 一条记录长什么样

核心思路：存「当时发生了什么」，而不是存「界面长什么样」。比如润色的对比视图不存，打开时用原文和结果现算（TextDiff 已经有了）；动作本身存一份当时的完整快照，这样你后来改了 prompt 或删了动作，旧记录照样能看、能用当时的设置重跑。

{
  "id": "01JB…",  "schemaVersion": 1,
  "at": "2026-10-01T14:32:08+08:00",
  "trigger": { "via": "selection",          // selection | hotkey | ocr
               "app": "com.apple.Safari", "appName": "Safari" },
  "input":   { "text": "The quick brown fox…", "url": null,
               "truncated": false },
  "action":  { …当时这个动作的完整配置（PopBarActionConfig 原样）… },
  "engine":  { "provider": "deepseek", "model": "deepseek-v4-flash",
               "ms": 1240 },
  "outcome": { "type": "text",               // 决定用哪个展示组件
               "text": "敏捷的棕色狐狸…",
               "deliver": "compare",          // panel|compare|replace|append|copy
               "delivered": "replaced" },      // 实际结果：replaced / pasted / failed / viewed
  "status":  "ok",                            // ok | error | cancelled
  "parent":  null,                            // 重跑出来的记录指向原记录
  "audio":   null                             // 朗读：SpeechCache 的 key
}
几个关键决定
  • outcome.type 决定展示，action.kind 只用来筛选和分组。因为「怎么展示」取决于产出了什么，而不是什么动作产出的：AI、脚本、快捷指令、系统翻译，产出的都是一段文字，用同一个文字组件展示就行。
  • outcome 的类型清单（比 11 种呈现方式合并了一些）：text、message（报告/错误）、link、file、speech、silent（复制、没有输出的快捷指令）。
  • 认不出的类型不丢：老版本读到新版本写的未知 type，用一个通用组件展示原文和原始字段，并照原样保留——和现在动作配置处理 unsupportedKindRaw 是同一个思路。
  • 中断的也记：流式输出到一半被你关掉，记成 cancelled，保留已经出来的那部分。
  • 太长的文字截断，不丢弃：超过上限（比如 10 万字）只存前面部分，标 truncated。

4 · 每种动作怎么绑定：展示 + 复现

这张表就是「动态展示」的规则。免费 本地完成；花钱 会再调一次云端模型或语音，界面上要标出来，免得误点。

动作种类记成什么 outcome历史里怎么展示能怎么复现

ai（润色这类 compare 输出）text · compare删改标红绿的对比视图（打开时现算）同上；另外显示「当时替换成功了没有」
systemTranslatetext双语对照（源语言 → 目标语言）复制　替换　重跑 免费（本机翻译）
transformtext（字数统计是 message）前后对照，JSON 之类用等宽字体重跑 免费　复制　替换
shortcut / scripttext / silent / message(出错)输出；出错时显示退出码和错误输出重跑 免费，但脚本会有副作用，重跑前要确认；脚本仍要过原来的「首次运行批准」
speakspeech小播放器 + 文字，播放时逐词高亮（时间戳已经在缓存里）本地缓存还在 → 直接播放 免费；缓存被清掉了 → 重新合成 花钱，按钮上写明

copysilent默认不记（设置里可开）再复制一次
pause / inspect / settings—不记，它们不处理文字—
出错（没配 key、网络失败、脚本退出码非 0）status = error红色错误框 + 原文修好后「重试」
以后新加的种类 / 输出新 type没写专门组件前：通用组件（原文 + 原始字段）只要动作种类认识，就能重跑

以后加新类型，要做什么

  1. 在 HistoryOutcome 里加一个 case。它是从 PopBarPresentation 转换过来的，转换用 Swift 的完整 switch，新加的呈现方式如果忘了处理历史，编译直接报错，不会悄悄漏记。
  2. 写一个展示组件，注册到「type → 组件」的表里。三个方法：列表里一行怎么写、详情怎么画、有哪些复现按钮。
  3. 没写组件也能上线：先用通用组件兜底，看得到、不丢数据。
筛选条也是动态的：页面顶部的筛选按钮从你当前的动作列表生成（你的「翻译」「润色」「语法检查」…），不是写死的分类。动作被删了，它的历史还在，归到「已删除的动作」。

5 · 「复现」分四层

层级做什么例子花不花钱
① 原样查看当时看到的结果再看一遍，包括对比视图翻出昨天润色前后的对比免费
② 再送一次把已经有的结果重新送出去，不重新计算复制、替换到现在选中的文字、重新打开链接、播放缓存音频免费
③ 重跑同一段原文、同一个动作再跑一次；可以选「用当时的设置」还是「用现在的设置」，也可以换个模型。结果存成新记录，挂在原记录下，可以切换版本对比翻译不满意，换个模型再翻看动作：AI / 云端朗读 花钱
④ 换个动作跑拿这段原文去跑别的动作翻译完觉得要解释一下：直接在历史里点「解释」看动作

6 · 存储、保留、隐私

存在哪
  • 推荐：SQLite，用系统自带的 libsqlite3，不引入第三方库。文件放在 ~/Library/Application Support/QDuo/history.sqlite（和其他 app 自有数据放一起）。
  • 几个常用字段单独成列（时间、动作 id、种类、outcome 类型、来源 app、原文 hash），方便筛选；整条记录另存一份 JSON 列，不认识的字段原样保留。
  • 原文和结果建全文索引（SQLite 的 FTS5），搜中文英文都快。
  • 备选：每月一个 JSONL 文本文件。好处是能直接用文本编辑器看、和现在「配置文件可手改」的风格一致；坏处是搜索、删除单条、按时间清理都要整文件重写。几千条以后会明显慢。
  • 存储格式算是「不好改回来的决定」，真正动手前我会找 Frank 再过一遍。
保留和隐私（都做成设置项）
  • 总开关「记录历史」；保留时长 7 天 / 30 天 / 90 天 / 永久；条数上限。
  • 不记录的 app：沿用现有的忽略规则，另外默认排除密码管理器（1Password、钥匙串访问等）。
  • 可以按动作关掉记录（比如你自己写的某个脚本）。
  • 朗读音频复用现有的 SpeechCache（上限 500 MB，最久没播的先删）。历史只记缓存的 key，不另存一份音频；缓存被清了，按钮自动变成「重新合成（花钱）」。
  • 历史只在本机。内容永远不进日志、不进统计（#11 的统计只数次数）。
  • 单条删除、按条件批量删除、清空全部。清空前二次确认。

7 · 入口

  • 设置窗口侧边栏加一页「历史」（原型里放在「动作」下面）。
  • 菜单栏图标的菜单里加「历史…」。
  • 结果面板标题栏加一个小时钟按钮：看这段文字之前处理过的结果。
  • 可选：一个全局快捷键打开历史。

8 · 分几步做

阶段内容
第 1 步记录 + 存储 + 设置项（开关、保留时长、排除 app）。先只记，界面可以是最简单的列表。
第 2 步历史页：选定的布局（A / B / C）、搜索、筛选、每种类型的展示组件、复现 ①②。
第 3 步复现 ③④：重跑、换模型、版本切换；朗读回放逐词高亮。
第 4 步菜单栏入口、结果面板的历史按钮、快捷键。

方案 A · 三栏时间线（像「邮件」app）

左边是设置窗口原有的侧边栏，中间按时间倒序列出每一条，右边是选中那条的详情和复现按钮。最「标准」的 macOS 做法，信息密度高，适合快速找某一条。点列表里的不同条目，看右边如何随类型变化（翻译、润色对比、朗读播放器、链接卡片、文件、出错、未来未知类型）。

QDuo
🔍

好处

扫一眼就能看到很多条；键盘上下键切换很顺；详情区够宽，润色对比、长文本都放得下。和 Mail、备忘录的习惯一致，不用学。

代价

列表里每条只有一两行，翻译和润色这类要看结果的，得点开才看得到。设置窗口要够宽（三栏至少 ~900pt）。

方案 B · 卡片流（像聊天记录 / 剪贴板历史）

每条记录是一张卡片，不用点开就按类型直接画出内容：翻译是双语对照，润色直接显示红绿对比，朗读带播放器，搜索是链接卡片。按天分组，往下滚就是更早的。适合「回看今天都干了什么」。

QDuo
🔍

好处

内容一眼可见，回看最省事；每种类型的「样子」最突出，最能体现按类型动态展示；不需要很宽的窗口。

代价

一屏只能放 4～6 条，找很久以前的某一条要靠搜索；长文本卡片要折叠，否则一张卡占满屏；卡片多了滚动性能要注意（SwiftUI 要用懒加载列表）。

方案 C · 按原文归组（同一段文字的所有处理放一起）

左边列的不是「每次操作」，而是「你选过的每段文字」。同一段文字先翻译、又解释、又朗读，归到一组。右边上方是原文，下方每个动作一个页签，同一个动作跑过多次就能切版本对比；最下面一排是你所有的动作，点一下就拿这段原文去跑（复现第 ④ 层）。

QDuo
🔍

好处

最适合「复现」和「对比」：同一段话换模型重翻、翻译完再解释，都在一个地方；像一个小工作台，历史不只是看，还能接着干活。

代价

不按时间看，「我刚才干了什么」要看左边的时间；链接、文件这类不太关心原文的记录放这里有点别扭；归组规则（原文完全一样才算一组？去掉首尾空白？）要定清楚。

三个方案对比

A · 三栏时间线B · 卡片流C · 按原文归组
最适合找某一条回看今天干了什么同一段话反复处理、对比
不点开能看到结果吗只有一行摘要能，按类型完整画出点原文后能看到全部动作
复现入口详情区底部按钮每张卡片底部按钮页签 + 底部「用其他动作跑」
多版本对比详情区里切版本卡片里切版本最自然（同一页签里切）
窗口宽度要求高（三栏）低中高
实现量（相对）中中中偏高（多一层归组）
底层存储完全相同。三个方案只是同一份数据的三种看法，以后加「切换视图」也不用动存储。
我的建议：A 做主视图，把 C 的「用其他动作跑」放进 A 的详情区。A 最稳，找东西最快；C 最有价值的那部分（同一段原文换动作、换模型、多版本对比）可以作为 A 详情区里的一块，不需要整个页面都按原文组织。B 的「按类型直接画出内容」也可以借过来：A 的列表行对翻译和润色多显示一行结果预览。

需要你拍板的问题

  1. 布局：A / B / C，还是按我的建议 A + C 的「换动作跑」？
  2. 存储：SQLite（推荐）还是 JSONL 文本文件？
  3. 默认保留多久：30 天（推荐）/ 90 天 / 永久？
  4. 「复制」动作默认记不记：我建议不记，它只是把选区复制一下，记了大多是噪音。
  5. 重跑默认用哪个设置：「用现在的动作设置」（推荐，你改了 prompt 通常就是想用新的），旧设置作为备选按钮？
  6. 要不要我把这份方案建成 GitHub issue（英文）？
