流程（三种布局共用）

首次启动老用户不显示→ 欢迎→ 辅助功能 · 必需每秒检查，打开开关就变绿→ 屏幕录制 · 可选可能要重开 QDuo，重开后回到这一步→ AI 模型 · 可选选服务商、贴密钥、挑动作→ 试一试选中示例文字看弹窗→ 完成以后不再自己出现

任何时候关窗口都行：进度记下来，菜单栏里多出一项「完成设置…」（只在辅助功能还没开时显示）。不弹通知、不定时提醒、下次启动也不会自己跳出来。

A 单独的向导窗口，左边列步骤

一个 740×520 的窗口，样式和设置窗口一家：左边是步骤列表（带「必需 / 可选 / 已完成 / 已跳过」），右边是当前这一步。可以点左边随便跳。

↑ 可以点：「打开系统设置」会模拟你去开了开关；屏幕录制会模拟「开了但没生效 → 重开」。

  • 只在第一次启动时自动出现一次。关掉就是关掉：不弹通知、不定时提醒、下次启动也不会再跳出来。唯一的提醒是现有的「图标变暗」+ 上面那一项菜单。

主要风险多一个窗口，要保证它和设置窗口不同时抢到前面纯线性，跳过可选项后不容易找回来第一次的体验不像「欢迎」，而像「请配置」
推荐 A，顺手借用 C 的一点：向导完成后，永久入口放在 设置 → 通用（而不是菜单栏里常驻一项）。
理由：QDuo 第一次打开时用户最需要知道的是「只有一件事必须做，其余两件可以跳」——A 的侧栏一直把这句话摆在眼前；屏幕录制要重开时，A 重开后的画面（同一窗口、左边带勾）最能让人明白是接着来；A 的每个页面都是 SwiftUI 小页面，权限轮询、钥匙串、模板这些逻辑已有，主要新增的是窗口本身和「重开自己」。
如果你更看重省事，C 是很好的退路：代码最少，但第一次的感受会差一截。B 最好看，但线性流程碰上「重开」和「跳过」时最容易让人迷路。

需要你拍板的问题

  1. 「试一试」在哪儿试？ QDuo 的弹窗现在不会在自己的窗口里出现（PopBarController.swift:139）。 A) 只给向导里那段示例文字开个口子（推荐，体验最好；改动小但要碰弹窗的判断逻辑）； B) 不改弹窗，这一步改成「打开备忘录，粘好一段示例文字，去那儿试」。
  2. AI 那一步的「测试」按钮会真的发一次很短的请求（花极少量 token），用来确认密钥能用。要不要？（推荐要）
  3. AI 模板默认勾不勾？推荐都不勾，让用户自己挑，避免弹窗一下塞满。
  4. 老用户升级后要不要也看一次？推荐不看，只在设置 → 通用里放入口。
  5. 选哪个布局：A / B / C？

实现要点（推理自代码，均未验证）

  • 辅助功能：点按钮先调一次 AXIsProcessTrustedWithOptions(prompt: true)（系统只在第一次弹自己的对话框），同时打开 x-apple.systempreferences:…?Privacy_Accessibility；向导可见时每 1 秒 + 收到 NSApplication.didBecomeActiveNotification 时调 store.refreshTrust()，窗口关掉就停。
  • 屏幕录制：CGRequestScreenCaptureAccess() 一个 app 一辈子只会弹一次系统框，之后是静默的，所以按钮一律同时打开系统设置。用户点过「打开系统设置」并切回 QDuo、而 CGPreflightScreenCaptureAccess() 仍是 false，就进入「可能需要重开」状态。在检测到 true 之前绝不显示「已开启」。
  • 重开自己：先把「当前在第几步」写进 UserDefaults，再启动一个 /bin/sh -c "sleep 0.5; open -n '<app 路径>' --args --onboarding" 后 NSApp.terminate；新进程看到 --onboarding 就打开向导并落在记下的那一步。系统自己弹的「退出并重新打开」走的是普通启动，所以也要在普通启动时检查「向导没做完 + 上次停在屏幕录制」→ 自动回到这一步（这是唯一一种向导会自己再出现的情况，因为是用户刚刚主动触发的）。
  • AI 模板：勾选的动作追加到动作列表末尾，等同于「动作 → 从模板添加」，不打开编辑器。
  • 向导窗口和设置窗口共用 AppState，在一边改了另一边立刻同步；首次启动不再自动打开设置窗口，改为打开向导。
