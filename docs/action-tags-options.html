三个方案对比

A · 文字小标签（推荐）B · 小图标C · 写进副标题
扫一眼能不能看出「哪些会改我的文档」能，青色「替换 / 追加」能，但要认得图标要逐行读字
第一次看懂不懂懂，都是中文词不一定，要悬停看说明懂
占的地方最多两个小标签最小右边不占，副标题可能被截断
缺 API Key 的提醒实心橙色，最醒目橙色三角橙色字
改动量小小小（副标题已经存在）

A 方案的具体规则

  • 什么都不标：复制、朗读、打开网址、网页预览、预览、在 Finder 中显示、分组，以及结果「显示在弹窗里」的文本处理——它们只在本机做事，不碰你的文档。
  • AI：会把选中的文字发给大模型（要花 token、要联网）。用的模型仍写在副标题里。
  • 缺 Key：AI 动作用的服务商还没设置 API Key——点了只会报错。代替原来的「需要 Key」。
  • 脚本：会运行 Shell 命令。快捷指令不标（它要在「快捷指令」app 里先建好，是你自己的东西）。
  • 替换 / 追加 / 复制：结果不显示在弹窗里，而是直接替换选中的文字、插到后面、或放进剪贴板。结果默认显示在弹窗里时不标。
  • 顺序固定：先「AI / 脚本 / 缺 Key」，再「替换 / 追加 / 复制」。一行最多两个。
