配置文件是怎么工作的

一个文件，两个人可以改它 —— 你和 App。这篇讲清楚它们怎么不打架、为什么你手写的东西不会被吃掉，以及「两条反应路径」到底是什么意思。

1 · 这个文件是什么

设置窗口里的每一项，都存在这一个文件里。不再有散落在系统偏好设置数据库里的几十个键，也不再有单独的动作 JSON 文件。你随时能打开它、能 git diff、能软链进 dotfiles 仓库、能拷到另一台机器上。

~/.config/qduo/
├── config.json          ← 所有设置都在这儿
└── config.schema.json   ← 自动生成，给编辑器用的

为什么是 ~/.config 而不是 Application Support。Application Support 在访达里默认是隐藏的、路径里带空格、没人会把它软链进 dotfiles —— 那是放「App 自己的东西、用户别碰」的地方。这个文件正好相反，它就是给你改的。你的 starship.toml 已经是这么放的。

API Key 不在里面。密钥留在系统钥匙串。这是刻意的：正因为文件里没有密钥，它才能放心地提交进一个公开仓库。

{
  "$schema": "./config.schema.json",
  "version": 1,
  "popup":  { "style": "liquidGlass", "resultFontSize": 16 },
  "wheel":  { "outerRadius": 116, "innerRadius": 53 },
  "ocr":    { "enabled": true, "hotKey": "shift+cmd+s" },
  "models": { "provider": "deepseek", "model": "deepseek-v4-flash" },
  "actions": [ /* 你那 7 个动作 */ ]
}

快捷键写成 "shift+cmd+s" 而不是 {"keyCode":1,"carbonModifiers":768} —— 后者是系统接口要的形状，对着它没法改。

关于注释

JSON 写不了注释，这是选 JSON 唯一的真实代价。换来的是：schema 文件让编辑器给你自动补全、列出某个字段的合法取值、鼠标悬停显示说明 —— 而且 App 回写文件时不会把它弄没。换成 TOML 能写注释，但 App 一回写，你写的注释就全没了，那更糟。

2 · 两个方向，谁都能改

这个文件有两个作者：你（在编辑器里）和 App（你点设置界面的时候）。难点全在「怎么让两边不互相覆盖，又不陷入死循环」。

图 1. 写是「立刻改内存、0.4 秒后落盘」——拖滑块一秒钟产生几十次变化，不攒一下的话文件会被写烂。读是「每秒 stat 一次」，变了才真的去读。

为什么是每秒轮询，而不是文件监听

这一条我原来做错过，而且是跑出来才发现的，光看代码看不出来。macOS 的文件监听（DispatchSource）看起来更精确，但在这件事上全是洞：

  • 监听目录：看不见「就地改写」。目录事件只在文件被创建、删除、改名时触发。很多编辑器（包括 vim 在文件是软链时）是就地改写的 —— 完全静默。
  • 监听文件：挺不过「原子替换」。原子保存是「写临时文件 → rename 盖过去」，换掉了 inode，老的文件描述符从此变聋。
  • 文件是软链进 dotfiles 时：上面两个还都盯错了目录 —— 真实文件在 dotfiles 仓库里，而监听挂在 ~/.config 这一侧。

要覆盖这三种情况得同时开两个监听、解析软链、删除时重新挂载、还要处理文件还不存在的情况。而一次 stat 是几微秒（走 vnode 缓存），每秒两次，对以上所有情况一概免疫。一秒的延迟，比你从编辑器切回浏览器的时间还短。

死循环是怎么断开的

最容易出的 bug：App 写文件 → 触发「文件变了」→ App 读回来 → 觉得不一样 → 又写 → 无限循环。

图 2. 用「一个标志位表示我正在写」会漏：通知是异步到的，经常在你把标志清掉之后才到。比内容就不会 —— App 自己写出去的字节，一定等于它记着的那串。

3 · 为什么你手写的东西不会被吃掉

这是整套设计里最要紧的一条，分两层。

第一层：整个文件按「JSON 树」存，不按结构体存

常规做法是把 JSON 解析成一个 Swift 结构体。问题是：结构体不认识的字段，在解析的那一刻就没了，下次保存写回去的时候自然也就不见了。你在文件里手写一个 App 还不认识的键（比如为了以后的版本先写上），或者用新版 App 写了个键再用旧版打开 —— 都会被悄无声息地删掉。

图 3. 区别不在于代码写得多仔细，而在于结构不一样：App 只会去动 popup.style 这种它明确知道的路径，别的字段它根本没有机会碰到。

第二层：动作列表里的每一个动作，单独再保一次

有个例外：动作是要解析成结构体的（App 得知道每个动作的标题、图标、提示词、属于哪个分组）。所以上面那套对动作内部不成立 —— 你在某个动作上手写一个字段，只要动过列表（改一个动作、拖一下顺序、删一个），全部动作的未知字段都会被抹掉。

所以动作结构体里加了一个「收纳格」：解析时把所有不认识的键收进去，写回时再原样吐出来。这不是新发明 —— 代码里本来就有一个只针对 kind 字段的同类机制（防止旧版 App 把新版做的动作类型改坏），现在把它从一个字段推广到所有字段。5 个单元测试锁住

4 · 四道保命的门

这些都是「不会丢你东西」的承诺，每一条都对应一个具体的失败场景。

门挡住的是什么验证
写之前先读盘 你在 vim 里保存，0.1 秒后 App 的延迟写落盘、把你的改动盖掉。现在 App 写之前先看一眼盘上的内容，发现变了就先把那一版另存成 .bak-时间戳 再写。你打的字永远有一份在。 已实测
解析失败不覆盖 文件里少个逗号 → App 读不懂。此时绝不用默认值把它盖掉（那是你的劳动成果，错的多半只是一个标点）。而是另存一份 .bad-时间戳，日志里大声说，然后用上一次好的设置继续跑。你改边正在编辑、文件暂时不合法的那几秒，App 就是静静等着。 已实测
空列表是你的决定 你把动作删光 → 下次启动 7 个默认动作全回来了，等于没法真正清空。现在只有「字段缺失或读不懂」才用默认值。 已实测
退出时同步写盘 改完设置马上退出 App，写操作还在后台队列里排队，进程就被杀了 —— 改动没了。现在写盘是同步的，函数返回时字节已经在盘上。 已实测
（附带）软链不会被写坏 你把 config.json 软链进 dotfiles 仓库之后，原子写会把软链本身替换成普通文件，dotfiles 那份停在旧内容，两边悄悄分叉。现在所有读写先解析软链。 已实测

5 · 「两条反应路径」是什么意思

你问的就是这个。用最具体的例子讲：「换一个快捷键」这件事，需要做两件事 —— 一是把新快捷键记下来（存进配置文件），二是去系统里把旧快捷键注销、把新的注册上。第二件事不做，你改了也没用。

问题在于，「改快捷键」有两个入口：你在设置窗口里录一个，或者你在配置文件里手写一行。现在的代码是这样的：

图 4. 「重新注册快捷键」这个动作，在两条路径里各写了一遍。以后加第三个需要副作用的设置时，很容易只在设置窗口那边加、忘了文件重载那边 —— 于是「手改文件不生效」。

这不是假想的隐患，它真实发生过。前面那个「总开关」就是这个坑：设置窗口里的开关会同时「记下来」和「真的启停监听」，而文件重载那条路只「记下来」了。结果就是手改文件把开关关掉，配置里显示关了，监听却还在跑。我当时是单独在重载那条路上补了一遍，才没漏。

Frank 的建议是把它变成一条路：

图 5. 设置窗口不再直接指挥任何东西，它只改数据。需要做副作用的那几处（快捷键、语言、模型）各自盯着自己关心的那个字段，谁改的它们都不关心。「界面改的」和「文件改的」从此没有区别。

代价：设置界面现在那 15 个「setXxx」方法会全部消失，换成「只改数据」；控制器那边要新增几处订阅。改动面不小，而且要动已经跑通的代码。

我的判断：方向是对的，但不是现在做。它预防的那个具体 bug 我已经单独处理掉了；等以后要加第三、第四个「改了要立刻生效」的设置时，再一次性改过来更划算 —— 那时候收益才真正大于风险。

6 · 为什么没拆成两个文件

Frank 建议把动作单独拆成 actions.json，理由是「调个滑块就会重写整个动作区域，万一动作解析出过问题，就会把默认值覆盖到你手写的内容上」。

这个担心在他假设的实现里成立，在实际实现里不成立：动作在内存里是以原始 JSON 树的形式存着的，只有你真的改了动作时才会重新编码。调滑块只会改 wheel.outerRadius 那一条路径，动作那一段是原样搬过去的 —— 它根本没被解析过，也就谈不上被默认值覆盖。

加上你明确说了要一个文件，所以保持一个。

7 · 拿掉任何一块会怎么样

拿掉…会发生什么严重度
JSON 树（改用结构体）你在文件里手写的任何 App 不认识的字段，下次保存就没了高
动作的「收纳格」同上，但只针对动作内部；改一个动作就会抹掉所有动作的未知字段高
写前备份你在编辑器里刚保存的内容，可能被 App 的延迟写盖掉，且无处可寻高
解析失败保护文件里打错一个字符，整份配置被默认值覆盖高
同步写盘改完马上退出 App，改动丢失中
解析软链软链进 dotfiles 后，App 一保存就把软链替换成普通文件，两边分叉中
字节比对App 写 → 收到通知 → 又写，无限循环，文件疯狂改动中
写入去抖（0.4 秒）拖滑块时每帧写一次盘，编辑器里的文件疯狂闪烁低
schema 文件编辑器里没有自动补全和字段说明，只能对着 JSON 猜低
