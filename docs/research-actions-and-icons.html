QDuo：下一步加哪些动作，图标盘怎么扩

调研日期 2026-09-23 · 对照 PopClip、SnipDo、Easydict、Bob、nextai-translator（原 openai-translator）、Pot、Raycast、Alfred、Apple Writing Tools，以及 PopClip 论坛、GitHub issues、V2EX、少数派上的用户反馈

先看结论

  1. 最该先做：AI 结果「替换原文」（对应 QDuo issue #2）。这是中英文两边证据最强的一项：PopClip 论坛浏览量最高的扩展帖（16,053 次浏览）要的就是它；Pot、nextai-translator、Bob 都有人专门提；PopClip 官方 OpenAI 扩展和 Raycast 都把「替换选区」做成了标准输出方式。做法：结果面板加一个「替换」按钮，外加每个动作可选的默认输出方式（面板 / 替换 / 追加到后面 / 只复制）。P0 工作量 M
  2. 第二：新增「打开网址模板」动作类型。一个类型、一个 {text} 占位符，就能覆盖搜索（Google/百度/Kagi/必应）、系统词典（dict://）、地图、GitHub 搜索、写入 Obsidian（obsidian://new）等几十个模板。成本最低、覆盖面最大。P0 工作量 S
  3. 第三：三个新的本地类型——「朗读」（系统语音，S）、「本地文本处理」（大小写、排序去重、合并 PDF 断行、繁简、中英文加空格、JSON 格式化、字数统计，M）、「运行快捷指令 / 脚本」（把选中文字交给 Shortcuts 或 shell，结果回到面板或替换原文，M）。最后一个是万能出口：存到备忘录、提醒事项、flomo、Anki 都能靠它做，不用 QDuo 一个个去接。P1
  4. 不用写代码、只加模板的 AI 动作：总结、语法纠错、改语气（正式 / 口语 / 精简）、语法解析、解释代码。都是现有 ai 类型换一段 prompt。
  5. 默认动作建议只加 2 个：「搜索」（网址模板）和「朗读」。其余都放进「模板库」里让用户自己挑——胶囊只有一行，默认塞太多反而难用。
  6. 图标盘从 48 个扩到 152 个，分 14 组；原来 48 个全部保留（用户已选的图标不会从选择器里消失）。每个名字都用 Apple 自带的可用性表核对过，最低都在 macOS 13.0 以内。注意 translate 这个很自然的图标要 macOS 14.4 才有，不能用。

一、要新增哪些动作「类型」

QDuo 今天的动作类型（PopBarActionConfig.Kind）是：copy、ai、webPreview、quickLook、revealInFinder、group；输出方式（PopBarPresentation）是：无界面、结果面板、小浏览器、Quick Look、Finder。下面这些候选动作里，大部分不需要一个动作一个类型，而是归到少数几个新类型/新输出里：

新增的东西是什么一次解锁哪些动作工作量
输出方式：替换 / 追加 / 复制
给 ai（以及后面的文本处理、脚本）加一个 output 字段；结果面板加「替换」按钮		把结果写回原来的输入框，不再只能看、只能复制AI 润色后替换、翻译后替换、纠错后替换、大小写转换后替换……M
类型 openURL（网址模板）一个带 {text} 的网址，选中文字做 URL 编码后填进去；可选在默认浏览器打开，或在 QDuo 自己的小浏览器里打开（现成的 webPreview 窗口）各种搜索引擎、系统词典、地图、翻译网站、Obsidian/Things/Bear 等支持 URL scheme 的 AppS
类型 speak（朗读）用系统的 AVSpeechSynthesizer 读出选中文字，用 NLLanguageRecognizer 自动选中文/英文声音；再点一下停止朗读、跟读、听发音S

为什么不把「存到 Obsidian / 备忘录 / 提醒事项」各做一个类型：它们在 PopClip 里是 29 个笔记类扩展 + 12 个待办类扩展，一个个接会没完没了。Obsidian、Things、Bear 有 URL scheme，交给 openURL；Apple 备忘录、提醒事项、日历交给「快捷指令」，这样 QDuo 自己不用申请日历/提醒事项/自动化权限。

三、默认动作 vs 模板库

胶囊只有一行，默认动作越多，每次弹出越挤。建议分两层：

层内容理由
默认
新装即有		现有 7 个：翻译、润色、解释、网页预览、预览（Quick Look）、在 Finder 中显示、复制
+ 搜索（网址模板，默认 Google，用户可改成百度/Kagi）
+ 朗读
+ 结果面板上的「替换」按钮（不是动作，是 AI 结果的一个出口；只在原选区可编辑时出现）		搜索和朗读是各家同类工具都内置的两项；「替换」按钮直接解决 issue #2，而且比「润色后自动替换」更安全——用户先看一眼结果再决定
模板库
设置里一键添加		AI：总结、语法纠错、改语气（一个 group 里放正式/口语/精简）、语法解析、解释代码
本地：大小写、命名风格、排序去重、合并断行、繁简、拼音、中英文加空格、JSON、清理链接、字数统计、系统词典、二维码
网址：百度、Kagi、必应、DuckDuckGo、维基百科、GitHub、地图、在 ChatGPT/Claude 网页中继续问、写入 Obsidian
快捷指令：存到备忘录、加到提醒事项、加到日历、加入 Anki		需求真实但因人而异；做成模板既能被找到，又不占胶囊位置

模板库本身也是一个小功能：设置页「添加动作」时多一个「从模板添加」的列表，每个模板就是一份预填好的 PopBarActionConfig（和现在的 DefaultActions.seed() 同一种写法），不需要新的数据格式。

四、「替换原文」怎么做、风险在哪

这是 P0，单独说一下思路（未实现、未验证，只是读代码后的方案）：

  1. 弹出时记下来源：选区来自哪个 App（进程号）、哪个输入框（Accessibility 元素）、这个元素的选中文字能不能被改（AXUIElementIsAttributeSettable 查 kAXSelectedTextAttribute）。不能改的（网页正文、PDF、截图 OCR 来的文字）就不显示「替换」按钮。
  2. 优先走 Accessibility 直接写：对原生 AppKit 输入框，把结果设给 kAXSelectedTextAttribute，不碰剪贴板。
  3. 写不进去再走粘贴：先把用户剪贴板整份存下来 → 放入结果（标记成临时内容 org.nspasteboard.TransientType，剪贴板管理器会忽略它）→ 激活来源 App → 发 ⌘V（仓库里已有 KeySender，加一个 paste() 即可）→ 稍等后把原剪贴板放回去。Electron、浏览器里的输入框基本都得走这条。
  4. 「追加到后面」：同样的路径，内容换成「原文 + 空行 + 结果」。

风险：① 用户在结果流式输出期间点了别处，选区已经变了——替换前要确认焦点还在原来的元素上，不在就退化成「已复制」并提示；② 剪贴板恢复的时机太早会把结果粘成旧内容，太晚会和用户自己的复制打架，需要实测几款 App（微信、飞书、VS Code、Chrome、备忘录）；③ 在代码编辑器里替换会打断撤销历史，但 ⌘V 路径一般可以 ⌘Z 撤回。

六、图标盘扩充（152 个）

现在编辑器里的图标盘是 48 个。新表 152 个，其中原有 48 个全部保留、新增 104 个（带橙色边框和「新」字），按上面动作表的需要分成 14 组。每格下方小字是该图标最早可用的 macOS 版本。

怎么核对的
  • 名字存在：在这台 Mac（macOS 27.0）上用 NSImage(systemSymbolName:accessibilityDescription:) 逐个取图，152 个全部取到、没有一个返回 nil；下面的图就是这样渲染出来的。
  • macOS 13 能用：这台 Mac 比 13 新，所以「取得到」不代表 13 上也有。我读了系统自带的 Apple 官方可用性表 /System/Library/CoreServices/CoreGlyphs.bundle/Contents/Resources/name_availability.plist（和 SF Symbols App 用的是同一份数据），它给每个名字标了首次出现的年份，再换算成 macOS 版本。152 个里最晚的是 macOS 13.0，没有一个晚于 13.0。分布：macOS 10.15：102 个，macOS 11.0：33 个，macOS 11.3：1 个，macOS 12.0：10 个，macOS 13.0：6 个。
  • 被我排除的：translate（macOS 14.4 才有——做「翻译」图标最顺手的一个，但不能用）、apple.terminal（14.0）、textformat.characters（15.0）。
  • 没做到的：没有在真正的 macOS 13 机器上跑过。图的样子是 macOS 27 的画法，13 上同名图标笔画可能略有不同，但名字可用性以 Apple 这份表为准。
