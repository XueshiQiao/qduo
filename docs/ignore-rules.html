忽略规则：哪些地方选中文字不弹出

有些地方选中文字不是为了翻译或提问，比如浏览器地址栏——选中只是为了改网址。忽略规则用「选中文字所在的界面元素长什么样」来认出这些地方，认出来就不弹出。规则只在 App 内部维护，用户看不到、也改不了；用户只有一个总开关。

一、它在哪、怎么生效

  • 规则写在 Sources/PopBar/Selection/SelectionIgnoreRules.swift 的 builtInJSON 里，是一段 JSON。
  • 每次选中文字、准备弹出时，QDuo 在后台线程拿到当前获得焦点的界面元素（键盘输入会进的那个元素），从上到下逐条比对规则；命中第一条就不弹出，并在日志里记一行 trigger ignored — <规则名>。
  • 带 "setting" 的规则跟着对应的设置开关走。现在只有一个开关：「通用 › 浏览器地址栏里不弹出」（配置文件里是 popup.ignoreAddressBars，默认开）。不带 "setting" 的规则始终生效。
  • 比对只读取几个属性，通常几毫秒；带「上级」条件的规则要往上查最多 40 层，也在十毫秒量级。

二、一条规则的写法

{
  "name":     "Safari address bar",          // 必填。日志和「检查元素」里显示的名字
  "setting":  "ignoreAddressBars",           // 可选。跟哪个设置开关走；不写 = 始终生效
  "apps":     ["com.apple.Safari"],          // 可选。只在这些 App 里生效（Bundle ID，不分大小写）；不写 = 所有 App
  "element":  { "AXIdentifier": "WEB_BROWSER_ADDRESS_AND_SEARCH_FIELD" },   // 必填。元素本身要满足的条件
  "ancestor": { "AXRole": "AXToolbar" },     // 可选。它的某一级上级（一直到窗口）要满足的条件
  "enabled":  false                          // 可选。写 false 暂时停用这条
}
字段必填含义
name是规则名。命中时写进日志，「检查元素」报告里也会显示「命中忽略规则：名字」。
element是条件表：属性名 → 匹配方式。全部满足才算这个元素命中。至少要有一个条件——空条件会匹配一切，所以会被直接丢弃。
ancestor否同样是条件表。从元素的父级开始往上找，只要有一级同时满足这里的全部条件就算命中；找到窗口（或 App）为止。
apps否Bundle ID 列表（也可以写单个 "app": "…"）。写了就只在这些 App 里比对。
setting否设置开关的名字。开关关掉时这条不生效。新增开关要在 PopBarPreferences.activeIgnoreRules 里把它传进去。
enabled否false = 停用。

匹配方式

写法意思例子
"值"完全相等（区分大小写）"AXRole": "AXTextField"
{ "equals": "值" }同上，显式写法"AXSubrole": { "equals": "AXSearchField" }
{ "contains": "片段" }包含这段文字，不分大小写、不分全角半角"AXDescription": { "contains": "search" }
{ "regex": "表达式" }正则表达式，找到一处匹配即可（要整串匹配请加 ^…$）"AXIdentifier": { "regex": "^search" }
  • 列表型属性（比如 AXDOMClassList，一个元素可以有好几个类名）：列表里任意一项满足就算满足。所以 "AXDOMClassList": "OmniboxViewViews" 的意思是「类名里有 OmniboxViewViews」。
  • 数字和真假值会先转成文字再比，例如 "AXEnabled": "true"。
  • 元素没有这个属性 = 不满足。
  • 写错的规则（没有 element、匹配方式拼错、正则写错、值写成了列表或对象）会被整条丢弃并在日志里警告，不会变成「匹配一切」。

三、能用来判断的属性

任何值是文字、文字列表、数字或真假值的辅助功能属性都能用。最常用的是下面这些——也正是「检查元素」报告里列出的：

属性是什么稳定性例子
AXRole元素的种类稳定，和语言无关AXTextField 输入框、AXTextArea 多行输入、AXStaticText 文字、AXWebArea 网页、AXToolbar 工具栏、AXGroup 分组、AXWindow 窗口
AXSubrole种类的细分稳定AXSearchField 搜索框、AXSecureTextField 密码框、AXStandardWindow
AXIdentifier开发者给元素起的固定标识最好用：和语言无关，版本间一般不变Safari 地址栏 WEB_BROWSER_ADDRESS_AND_SEARCH_FIELD
AXDOMClassList类名列表。Chrome 系浏览器的界面、网页里的元素都有浏览器界面的类名稳定；网页里的类名常被网站改版或打包工具改掉，慎用Chrome 地址栏 OmniboxViewViews
AXDOMIdentifier网页元素的 id / 浏览器界面的内部 id浏览器界面的常是临时编号（如 view_1012），不要用；网页里的 id 视网站而定
AXDescription、AXTitle给读屏软件念的描述、标题跟界面语言变，同一个 Chrome 地址栏在日文界面是「アドレス検索バー」。只在别无选择时用，并配合 contains
AXRoleDescription种类的本地化名字跟语言变，不要用「テキストフィールド」
AXPlaceholderValue输入框里的灰色提示文字跟语言、版本变
AXHelp鼠标悬停提示跟语言变
挑属性的顺序：AXIdentifier > 浏览器界面的 AXDOMClassList > AXRole/AXSubrole 加上级条件 > 描述类文字（最后手段）。尽量用和界面语言无关的属性——QDuo 的用户用各种语言的系统。

四、加一条规则的步骤

  1. 在「设置 › 操作 › 从模板添加 › 自动化」里添加「检查元素」动作。
  2. 到想屏蔽的地方选中文字，点「检查元素」。报告里有：所在 App 和 Bundle ID；元素的各项属性；从元素一层层往上到窗口的路径，每层写成 AXRole(AXSubrole) #标识 .类名 "描述"。如果这里已经被某条规则挡住、弹不出来，先在设置里关掉对应开关再检查。
  3. 从报告里挑一个稳定、唯一的属性（见上一节的顺序），写进 builtInJSON。只靠元素本身分不开时，再加 ancestor 条件或 apps 限制。
  4. 自测两件事：该挡的地方不弹出（日志里有 trigger ignored — 规则名），正常的地方照样弹出（网页正文、普通输入框）。
  5. SelectionIgnoreRulesTests 会检查 builtInJSON 里每一条都能解析——写错会让测试失败，而不是悄悄少一条规则。

五、例子

现有规则：浏览器地址栏

{ "name": "Chromium address bar", "setting": "ignoreAddressBars",
  "element": { "AXDOMClassList": "OmniboxViewViews" } },
{ "name": "Safari address bar", "setting": "ignoreAddressBars",
  "element": { "AXIdentifier": "WEB_BROWSER_ADDRESS_AND_SEARCH_FIELD" } }

实测：Chrome、Safari 都生效（2026-09-29）。Edge、Brave、Arc 用的是和 Chrome 同一套代码，按道理同一个类名也能认出，未实测。

写法示例（没有启用）

// 所有窗口工具栏里的输入框（地址栏、Finder/邮件顶部的搜索框…）
{ "name": "Toolbar text fields",
  "element":  { "AXRole": "AXTextField" },
  "ancestor": { "AXRole": "AXToolbar" } }

// 任何 App 里的搜索框（系统搜索框的子类型）
{ "name": "Search fields", "element": { "AXSubrole": "AXSearchField" } }

// 只在某个 App 里、描述里带 search 的输入框
{ "name": "Example search box", "apps": ["com.example.app"],
  "element": { "AXRole": "AXTextField", "AXDescription": { "contains": "search" } } }

六、局限

  • 比的是「获得焦点的元素」。在输入框里选中文字，它就是那个输入框；在网页正文里选中时，焦点常常是整张网页（AXWebArea）或网页里的某个链接，不一定精确到那段文字。所以规则最适合认「输入框、地址栏、搜索框」这类可聚焦的控件。
  • 不提供辅助功能信息的 App 认不出。有的 App 自己画界面、没给系统描述元素（部分游戏、个别 Electron 应用），这时规则不会命中，照常弹出——宁可弹出，也不误挡。
  • 网页里的类名、id 会随网站改版变化，针对网页内容的规则要预期会失效。
