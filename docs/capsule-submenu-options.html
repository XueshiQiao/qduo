胶囊条里的「分组」怎么展开

现在胶囊条没有第二层：一个分组会被拆开，把里面的动作全部平铺在条上（PopBarActionConfig.flattenedForCapsule）。你想要的是：指针滑到分组按钮上，弹出一个下拉，再选里面的一项。下面是三种做法，每种都画了几个关键时刻，最后有对比表和推荐。

现状：分组被平铺

示例配置：翻译、润色、解释、英文（分组，含 润色替换 / 单词 / 中译英 / TypoFix / 语法纠错）、搜索、复制。平铺后条上一共 10 个按钮，比原来宽了将近一倍；分组越多越长，靠近屏幕边时会被挤到一边。

V1 · 普通下拉菜单

分组按钮在标签旁多一个小 ⌄。指针停在上面约 150ms，或者点一下，就在按钮正下方弹出一个标准菜单，左边和按钮对齐；下方放不下时翻到条的上方。

交互细节

打开
悬停约 150ms 自动打开（指针只是路过不会弹）；点击也能立即打开。两种都支持。
按住-拖-松开
在分组按钮上按下、不松手往下拖到某一项、松开 = 直接执行。这是 macOS 菜单本来就有的手势，一次完成。
取消
Esc；点菜单外面；指针离开菜单并滑到条上别的按钮（菜单关闭，那个按钮进入悬停）。从按钮往菜单斜着走时，要有一个「宽容三角区」，不能一出按钮就关。
键盘
分组按钮有焦点时按 ↓ / 空格打开；↑↓ 选、回车执行、← 或 Esc 收起。菜单右侧显示 1–9 数字，按数字直接执行。
8 项以上
菜单最多显示 8 行，再多就在底部出现滚动箭头（系统菜单同款），滚轮或把指针停在箭头上自动滚。
屏幕边缘
下方空间不够就翻到条上方；左右贴边时往里推，保证整张菜单在屏幕内。
实现提示
可以直接用系统 NSMenu 弹出，翻转、滚动、键盘、按住拖松开都是现成的；外观是系统菜单，不是胶囊的毛玻璃（未验证：在 QDuo 的不抢焦点浮窗上弹 NSMenu 是否一切正常，需要实测）。

优点

  • 人人都认识，零学习成本。
  • 不遮挡条上的其他按钮，改主意可以直接滑去别的按钮。
  • 8 项以上、贴边翻转、键盘操作都有成熟答案，甚至可以直接用系统菜单。

缺点

  • 指针要从条往下走一段：选第 3 项约 90pt，最后一项约 140pt。
  • 条通常在选中文字上方，菜单往下开会盖住选中的那段文字。
  • 如果用系统菜单，外观和胶囊的毛玻璃不完全一致。

V2 · 垂直居中于条

菜单盖在条上，中间那一行正好落在指针所在的分组按钮上，那一行只是标题「英文」，不可执行（留空行的作用，防误触）。其余子项一半在上、一半在下，指针往上或往下滑一两格就到。这其实就是 macOS 弹出按钮（NSPopUpButton）的做法：菜单把当前项对准按钮。

交互细节

打开
悬停约 150ms 或点击。打开的瞬间指针在标题行上，什么都不会高亮、也不会执行——必须真的移动到某一项上。
按住-拖-松开
最适合这个方案：按下、往上或往下拖一格、松开。平均只要移动 24–48pt。在标题行上松开 = 什么也不做，菜单保持打开。
取消
Esc；点菜单外面；从菜单左右两侧离开。因为菜单盖住了条上相邻的 2–3 个按钮，想换别的按钮得先让菜单收起。
键盘
打开后 ↑ 从标题往上走、↓ 往下走；回车执行，Esc 收起。数字键 1–9 同 V1。
项目怎么分上下
规则：标题行永远对准指针；上方放 ⌊n/2⌋ 项，放不下就把多出来的挪到下方。所以贴近屏幕上边时会自动退化成「标题在上，全部往下」，贴近下边时反过来。
8 项以上
上下各最多 4 项，多出来的用上下两端的滚动箭头。
实现提示
NSMenu.popUp(positioning:at:in:) 本来就能指定「哪一项对准哪个点」，把标题行当作对准项即可（未验证：系统在空间不够时的自动挪动，和上面的规则是否一致）。

优点

  • 指针移动最少：常用的上下 2 项各只差一格（24pt）。
  • 上下两个方向都能用，和转盘（wheel）「从原地展开」的感觉一致。
  • 按住-拖-松开几乎是一个小抖动就完成。

缺点

  • 菜单盖住了条上相邻的按钮，打开后看不到也点不到它们。
  • 各项位置随屏幕位置变化（贴边时上下分配会变），难以形成肌肉记忆。
  • 对多数人是陌生的：「菜单往上也有东西」需要一两次才发现。
  • 向上的部分会盖住选中文字上方的内容，对位要求精确，做得不准会显得歪。

V3 · 原地换成子项 我的建议 · 额外方案

点一下分组按钮，整条胶囊原地换成这个分组的子项，最左边变成「‹ 英文」返回按钮。不弹任何新的浮层，指针只在同一行里左右移动，选项和平常的按钮长得一模一样。像 iOS 文字选择菜单里的「›」翻页，也像转盘展开第二圈时「原来那圈让位」。

交互细节

打开
只用点击，不做悬停打开——内容在指针底下整条替换，靠悬停触发会很晃，指针路过就把条换掉了。子项从分组按钮的位置向两边淡入（约 150ms）。
按住-拖-松开
不支持（换条之后按住拖不直观）。一次点开，再点一次执行。
取消
点「‹ 英文」、Esc 或 ⌫ 回到原来的条；整个浮窗关闭时自动还原，下次弹出总是一级。
键盘
←→ 移动，回车执行 / 进入分组，Esc 返回上一层。数字键对应条上从左到右的位置。
8 项以上
条最多放 8 个按钮（含返回），放不下的收进最后一个「更多」按钮，点开是 V1 那样的小菜单。
屏幕边缘
和现在的胶囊一样：条宽变化后按现有的贴边逻辑重新摆放；为了不让按钮在指针底下乱跳，保持条的左边不动，只在贴右边时才往左长。

优点

  • 不遮挡任何内容，不会盖住选中文字；没有第二个浮层要对齐。
  • 子项和普通按钮同一套样式（图标＋名字），视觉最统一。
  • 分组可以很多层（分组里再放分组）而不会越叠越高。

缺点

  • 多一次点击，而且不能悬停打开——和你「滑上去就弹」的设想不一样。
  • 整条换掉的瞬间，指针底下的按钮变了，第一次用会愣一下。
  • 子项名字只有 9pt 小字，长名字（语法纠错、润色替换）要截断或加宽。

推荐：先做 V1，并用同一套代码把 V2 做成一个设置项

V1 和 V2 在实现上几乎是同一件事：都是在分组按钮处弹一个菜单，区别只是「菜单顶对准按钮底」还是「标题行对准指针」。所以建议：

  • 默认 V1。人人都会用，不遮挡条上的其他按钮，8 项以上和贴边都有现成答案。
  • 设置里加一个开关「分组菜单位置：下方 / 居中」，居中就是 V2。喜欢最短移动距离的人（包括你自己试用）可以打开，用一阵再决定要不要换成默认。
  • V3 暂不做。它最干净，但必须多点一次、不能悬停打开，和你「滑上去就弹」的初衷相反；如果以后分组要嵌套多层，再回来考虑它。

以上都是设计判断，没有写代码、没有实测。「用系统 NSMenu 在 QDuo 的浮窗上弹出」是否顺利是最大的未知数，动手前要先做个小实验。

要你拍板的问题

  1. 悬停打开还是只点击打开？ A：悬停 150ms + 点击都行（推荐）；B：只点击，防止路过误弹。
  2. 菜单外观： A：系统原生菜单（省事、功能全，但不是毛玻璃胶囊风格）；B：自绘成和胶囊一样的毛玻璃（好看，但滚动、键盘、翻转都要自己写）。
  3. V1 往下开会盖住选中文字。 A：照常往下开（系统习惯）；B：优先往「远离选中文字」的方向开（条在文字上方时就往上开）。
  4. 要不要加「下方 / 居中」这个设置项，还是只做一种？
