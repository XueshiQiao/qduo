Design · issue #4 · 2026-09-30

快捷键弹出

选中文字以后按一个快捷键，把菜单弹出来。它和「暂停」是两个互不相干的开关：暂停只管选中文字以后会不会自动弹，快捷键只管按下去弹不弹。

起因

issue #4（用户 @yaoxinghuo）：「希望支持快捷键触发和框选文本两种触发方式」。选中即弹已经有了，缺的是「只在我想要的时候弹」——有些人嫌选中就弹太打扰。

两个开关，互相独立

开关管什么在哪里默认
暂停选中文字以后自动弹不弹菜单栏、设置侧边栏底部；配置 popup.enabled运行（会自动弹）
快捷键弹出按下快捷键弹不弹设置 → 通用 → 快捷键弹出；配置 popup.hotKeyEnabled + popup.hotKey关，而且没有预设组合键

四种组合，每一种都说得通：

用户想要的暂停开关快捷键选中文字按快捷键
正常使用（默认，和以前一样）运行关弹—
完全安静暂停关不弹—
只在按快捷键时弹（issue #4 要的）暂停开不弹弹
自动弹，外加快捷键兜底运行开弹弹

打开快捷键时自动暂停

两个开关虽然互相独立，但打开快捷键的人，绝大多数是想「只在按快捷键时才弹」。所以快捷键开始能用的那一刻（开关打开且已录好组合键，或者开关开着、第一次录好组合键），QDuo 会顺手帮用户暂停。

  • 只在「从不能用变成能用」这一下暂停一次。之后用户手动恢复，就是想要「两者都要」，不会再被暂停；改录别的组合键也不会再暂停。
  • 组合键还没录好时不暂停：否则会出现既不自动弹、也没有快捷键的状态，App 看起来像坏了。
  • 关掉快捷键时不会自动恢复（讨论时只定了「打开时暂停」，关掉时怎么办没有定，先不动）。这时如果还在暂停，侧边栏会显示「已暂停」，用户能看出来。
  • App 重启时不会触发暂停，只看设置里的开关动作。
为什么不做成「触发方式：自动 / 快捷键 / 两者」三选一？讨论时先是这么设计的，后来发现它和「暂停」管的是同一件事——选了「仅快捷键」就等于暂停，暂停按钮就成了一个按了没用的按钮。拆成两个互不相干的开关后，所有状态都由两个开关组合出来，没有哪个按钮会失效。第四种组合是白捡的：用键盘 Shift+方向键选的字，自动弹出认不出来，按快捷键可以补上。

快捷键不受任何例外限制

用户按快捷键是明确想要，而这些例外本来是为了防止「误弹」才设的。截图取词（OCR）的快捷键早就是这个规则。

例外选中自动弹按快捷键
暂停不弹弹
排除的 App（popup.excludedApps）不弹弹
浏览器地址栏（popup.ignoreAddressBars）不弹弹
QDuo 自己的窗口不弹不弹

一条读取流程，两个入口

两种触发走的是同一份代码（PopBarController.handleTrigger(_:)，参数 TriggerSource 是 .gesture 或 .hotKey）。区别只在最前面那几道「要不要继续」的检查。

为什么「是否暂停」要在读取之前判断，而不是弹框前

讨论时考虑过：前面一步不少地照常读，只在最后弹框前看一眼暂停。没这么做，因为读取可能会替用户按一次 ⌘C（Chrome、微信这类 App 只能这样读，读完再把剪贴板还原）。要是暂停时也照读，暂停期间每拖选一次，QDuo 都会在后台动一次剪贴板，剪贴板管理工具还可能把这些都记下来。暂停就应该什么都不做。

暂停时，监听鼠标的模块为什么还开着

快捷键开着的时候，暂停期间监听也不关。它只在旁边看，不读取、不弹框，只做两件事：

  1. 记下每次按下鼠标那一刻剪贴板的状态。终端（Ghostty + herdr、tmux 的鼠标模式、OTTY）里的文字是程序自己复制到剪贴板的，QDuo 判断「剪贴板是不是在这次选字之后变的」，靠的就是这个记录（CopyOnSelectStrategy）。不记的话，暂停时按快捷键在这些终端里就读不到。按快捷键时的规则是：剪贴板在上一次按下鼠标之后变过，就当作是选中的内容。
  2. 点别处时关掉快捷键弹出的菜单，和平时一样。

暂停且快捷键关着时，监听照旧完全关闭。

读取结果和正常情况一样吗

读取办法用在哪按快捷键时
直接问系统选中了什么（辅助功能接口）原生 App、Safari 等一样
读终端自己复制到剪贴板的内容Ghostty + herdr、tmux、OTTY一样（靠上一节的记录）。比较起点从「这次拖选开始时」变成「上一次按鼠标时」
替用户按 ⌘C 再读剪贴板Chrome、Electron、微信一样。发出的按键里只带 ⌘；用户手上还按着快捷键的修饰键时，个别 App 可能不认，讨论时认为问题不大，没有特殊处理

弹在哪里

  • 选中自动弹：弹在松开鼠标的位置（没变）。
  • 按快捷键：永远弹在鼠标所在的位置，不看选区在哪。
曾经的做法和为什么改掉：第一版是「能拿到选区位置就弹在选区上方，拿不到才弹在鼠标处」。实际用下来不行：圆环要用鼠标去点，如果它弹在离鼠标很远的地方，鼠标得划过去，途中经过别的 App 就可能让它消失；而且鼠标可能恰好停在圆环第二圈（子菜单）的位置，一弹出来就直接展开了子菜单。所以只能弹在鼠标处。

同理，查「选中的文字是不是链接」时，按快捷键的情况下跳过「鼠标下面是不是链接」这一步（LinkResolver 的 T2）：鼠标不在选区上，它正好停在某个网页链接上也跟选中的文字无关。这个问题是实测时发现的——第一次测试时它把另一块屏幕上网页里的一个链接当成了选区的链接。

其他规则

  • 没有预设快捷键。给所有人挑一个组合键，总会和某些人别的 App 冲突，按了没反应还发现不了。打开开关后，设置里提示去录一个。
  • 不能和截图取词的快捷键相同，两边设置时都会拒绝，显示「该快捷键已被占用」。
  • 快捷键被别的 App 占了：注册失败，保留原来那个，设置里提示被占用。
  • 按快捷键时没有选中文字：什么都不弹。
  • 没有辅助功能权限：按了也读不到，只写日志。
  • 侧边栏状态：暂停且快捷键可用时，显示「已暂停 · ⇧⌘C 仍可弹出」（换成实际的组合键），免得暂停了还在弹，看起来像坏了。

讨论过、没做的：按住修饰键再选

另一种方案是「按住某个键拖选才弹」。没做，因为每个修饰键拖拽时本来就有用处，而 QDuo 只能旁观、拦不住这个键：⇧ 是扩大选区，⌃+点击等于右键，⌘+点击是新标签打开或多选，⌥ 在终端和编辑器里是矩形选区（正好撞上 issue #8 那批终端）。而且得在动手选之前就决定要不要弹，快捷键则是选完再决定。
